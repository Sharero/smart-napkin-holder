# Умная салфетница

**Салфетки заканчиваются — администратор получает уведомление на телефон.**

Проект состоит из приложения для Android, программы для ESP32 и небольшого
сервера. ИК-датчик проверяет, есть ли бумага на выбранной высоте. Если стопка
опускается ниже этого уровня, приложение сообщает, что салфетницу пора пополнить.

> Сейчас проект можно показать без деталей: в приложении есть самостоятельный
> деморежим. Проверка на настоящем оборудовании ещё впереди.

[Демонстрация](#демонстрация-без-оборудования) · [Запуск](#запуск-сервера) · [Подключение](docs/hardware.md) · [Сценарий показа](docs/demo.md)

## Как это работает

```text
ИК-датчик → ESP32 → Wi-Fi → Сервер → Android → Уведомление
```

1. Датчик замечает, что салфеток на контрольной высоте больше нет.
2. ESP32 ждёт 3 секунды: это помогает отсеять случайное срабатывание.
3. ESP32 отправляет состояние на сервер.
4. Сервер сохраняет его в базе данных.
5. Приложение получает новое состояние и показывает предупреждение.
6. После пополнения салфетница снова получает статус «Салфетки есть».

Датчик определяет **достижение порога**, а не точное число салфеток.

## Что уже есть

| Часть | Возможности |
|---|---|
| Android-приложение | Панель администратора, уведомления, настройки сервера |
| Деморежим | Три виртуальные салфетницы, сценарий расхода, журнал событий |
| Прошивка ESP32 | Чтение датчика, Wi-Fi, повторная отправка при ошибках |
| Сервер | Хранение состояний и истории в SQLite, доступ по токенам |
| Симулятор | Отправка состояния с компьютера вместо ESP32 |

**Проверено:** три серверных теста и синтаксис Python.
**Пока не проверено:** сборка Android и прошивки, работа на телефоне и с датчиком.
Готового APK в репозитории нет.

## Демонстрация без оборудования

Сервер и ESP32 для этого режима не нужны.

1. Соберите и запустите приложение по инструкции ниже.
2. Разрешите уведомления Android.
3. На главном экране нажмите **«Запустить демонстрацию»**.
4. Через 5 секунд у стола 01 появится статус **«Пора пополнить»**
   и приложение отправит тестовое уведомление.
5. Нажмите **«Салфетки пополнены»**, чтобы вернуть обычный статус.

На экране отображаются три салфетницы, общая сводка и журнал последних 12 событий.
Состояние сохраняется после закрытия приложения. Если уйти с экрана во время
сценария, его таймер остановится. Плашка «Деморежим» обозначает моделируемые данные.

Подробный [сценарий показа](docs/demo.md) пригодится для презентации проекта.

## Сборка приложения Android

Самый простой способ — через [Android Studio](https://developer.android.com/studio).

### Что установить

| Инструмент | Версия |
|---|---|
| JDK | 17 |
| Android SDK Platform | 35 |
| Gradle | 8.9 |
| Android Gradle Plugin | 8.7.3, уже указан в проекте |

Приложение рассчитано на **Android 8.0 и новее**.

### Порядок действий

1. В Android Studio выберите **Open** и откройте папку `android`.
2. В **SDK Manager** установите Android SDK Platform 35.
3. В настройках Gradle выберите JDK 17 и Gradle 8.9.
4. Дождитесь загрузки зависимостей и синхронизации проекта.
5. Подключите телефон с включённой отладкой по USB или создайте эмулятор.
6. Нажмите **Run ▶**.

Gradle wrapper пока не включён. Если Gradle 8.9 уже установлен, можно создать его:

```bash
cd android
gradle wrapper --gradle-version 8.9
```

Для сборки APK из той же папки:

```bash
gradle :app:assembleDebug
```

Результат:

```text
android/app/build/outputs/apk/debug/app-debug.apk
```

Альтернативная установка SDK через командную строку описана в
[документации Google](https://developer.android.com/tools/sdkmanager).
В текущей среде скачать SDK не удалось: недоступно разрешение имени `dl.google.com`.

## Запуск сервера

Этот раздел нужен для подключения ESP32 или проверки через симулятор.
Достаточно **Python 3.10 или новее**, дополнительные библиотеки не нужны.
Компьютер с сервером должен оставаться включённым.

Откройте терминал в корне проекта. Команды ниже предназначены для Bash:

```bash
export DEVICE_TOKEN="$(python3 -c 'import secrets; print(secrets.token_hex(24))')"
export ADMIN_TOKEN="$(python3 -c 'import secrets; print(secrets.token_hex(24))')"
HOST=0.0.0.0 python3 server/app.py
```

Создаются два разных ключа доступа:

| Ключ | Где используется |
|---|---|
| `DEVICE_TOKEN` | В прошивке ESP32 и симуляторе |
| `ADMIN_TOKEN` | В Android-приложении |

Сохраните значения в менеджере паролей. Чтобы увидеть их в своём терминале:

```bash
printenv DEVICE_TOKEN
printenv ADMIN_TOKEN
```

Не публикуйте токены в скриншотах или репозитории. После перезапуска используйте
те же значения. В новом терминале их нужно задать заново:

```bash
export DEVICE_TOKEN='ваш-сохранённый-токен-устройства'
export ADMIN_TOKEN='ваш-сохранённый-токен-администратора'
HOST=0.0.0.0 python3 server/app.py
```

Сервер создаст файл `salfetki.sqlite3`. В нём сохраняются состояния и история.
По умолчанию используется порт `8080`.

## Проверка через симулятор

Пока ESP32 нет, её можно заменить командой с компьютера.
В другом терминале задайте тот же `DEVICE_TOKEN` и выполните из корня проекта:

```bash
export DEVICE_TOKEN='ваш-сохранённый-токен-устройства'
python3 tools/simulator.py --state ok
python3 tools/simulator.py --state low
python3 tools/simulator.py --state ok
```

- `ok` — салфетки есть.
- `low` — пора пополнить.
- Повтор одного состояния не создаёт новое событие.

Добавить другую салфетницу:

```bash
python3 tools/simulator.py --device table-02 --state low
```

Если сервер находится на другом компьютере:

```bash
python3 tools/simulator.py --url http://192.168.1.100:8080 --state low
```

Симулятор отправляет один сигнал за запуск. Если сигналов нет больше трёх минут,
сервер считает устройство недоступным, сохраняя последнее известное состояние.

## Подключение приложения к серверу

1. Откройте приложение и нажмите **«Настроить подключение к ESP32»**.
2. Введите адрес сервера и `ADMIN_TOKEN`.
3. Нажмите **«Сохранить и включить наблюдение»**.
4. Отправьте состояние через симулятор или включите ESP32.
5. Нажмите **«Обновить сейчас»**, чтобы сразу получить данные.

| Где запущено приложение | Адрес сервера |
|---|---|
| Эмулятор на компьютере с сервером | `http://10.0.2.2:8080` |
| Настоящий телефон | `http://IP-компьютера:8080` |

Например: `http://192.168.1.100:8080`. Телефон должен иметь доступ к компьютеру
по сети; для первого запуска подключите их к одному Wi-Fi.
Адрес `localhost` на телефоне указывает на сам телефон.

Когда приложение открыто, проверка выполняется каждые **10 секунд**.
В фоне используется WorkManager с интервалом **от 15 минут**; энергосбережение
Android может увеличить задержку. Мгновенные фоновые уведомления пока не реализованы.

Вернуться к виртуальным устройствам можно кнопкой **«Открыть демонстрационный стенд»**.

## Детали и подключение

Планируемые компоненты:

- Плата разработки ESP32-WROOM-32U.
- ИК-датчик препятствий TZT IR.
- Два аккумулятора LiitoKala HG2 18650, 3000 мА·ч.
- Модуль заряда и балансировки 2S Type-C, 8,4 В / 1,5 А.

**Дополнительно нужен понижающий преобразователь до 5 В.**
Два аккумулятора последовательно дают до 8,4 В — подавать это напряжение напрямую
на вход 5V платы нельзя. Для первых опытов используйте USB-питание.

Подключение GPIO27, установка датчика и требования к питанию описаны в
[инструкции по аппаратной части](docs/hardware.md). Точные параметры датчика,
зарядного модуля и платы нужно сверить с документацией продавца.

## Загрузка прошивки ESP32

Установите [PlatformIO](https://platformio.org/). Скопируйте файл
`firmware/src/config.example.h` в `firmware/src/config.h` и заполните:

| Настройка | Значение |
|---|---|
| `WIFI_SSID` | Название Wi-Fi, сеть 2,4 ГГц |
| `WIFI_PASSWORD` | Пароль Wi-Fi |
| `SERVER_URL` | Адрес сервера, доступный ESP32 |
| `DEVICE_TOKEN` | Ключ устройства |
| `DEVICE_ID` | Имя салфетницы, например `table-01` |
| `SENSOR_PIN` | GPIO датчика, по умолчанию 27 |
| `PAPER_PRESENT_LEVEL` | Уровень при наличии бумаги, по умолчанию `LOW` |

Затем выполните:

```bash
cd firmware
pio run
pio run --target upload
pio device monitor
```

При нестабильном сигнале состояние принимается после 3 секунд без изменений.
ESP32 отправляет контрольный сигнал каждые 30 секунд и повторяет отправку при ошибке.
Для HTTPS нужно заполнить `ROOT_CA` корневым сертификатом сервера.

## Проверка кода

Из корня проекта:

```bash
python3 -m unittest discover -s tests -v
```

Тесты проверяют ключи доступа, неправильные запросы, смену состояний,
отсутствие повторных событий, хранение истории и потерю связи.
HTTP-запросы проверяются в памяти, без открытия сетевого порта.

## Если что-то не работает

| Проблема | Что проверить |
|---|---|
| Не появляются уведомления | Разрешение Android, канал «Мало салфеток», режим «Не беспокоить» |
| Телефон не видит сервер | IP компьютера, общий Wi-Fi, запущенный сервер, доступ к порту 8080 |
| Ошибка HTTP 401 | В приложении нужен `ADMIN_TOKEN`, в ESP32 — `DEVICE_TOKEN` |
| На сервере нет устройств | Отправьте первое состояние через симулятор |
| Устройство потеряло связь | Проверьте Wi-Fi; симулятор отправляет только один сигнал |
| Датчик показывает наоборот | Проверьте `PAPER_PRESENT_LEVEL` и настройку чувствительности |
| Android-проект не собирается | Проверьте JDK 17, Gradle 8.9, SDK 35 и доступ к репозиториям зависимостей |

## Что ещё предстоит

Собрать электронику, настроить датчик с настоящими салфетками, проверить работу
на телефоне и измерить время работы от аккумуляторов. Заряд батареи пока не измеряется.
Точное число салфеток тоже не определяется.

HTTP предназначен для доверенной локальной сети. Для работы через интернет нужен
HTTPS и настройка доступа. В этой версии используются общие токены без учётных
записей администраторов; история событий автоматически не очищается.
